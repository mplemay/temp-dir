# Proposal

## Why

The prototype already loads territory, assay, and CRM feeds, but the home page is still a three-card index. Reps still cannot see who to call, ordered by impact. This change closes that data-to-insight gap with an offline ranked worklist so the site can ship a “Why Tempus, Why Now” call list without an OpenAI key at runtime.

## What Changes

- Add an offline ranking pipeline that joins the three committed feeds, scores every accepted provider with a deterministic mix formula, and uses OpenAI GPT-6 Luna (`gpt-6-luna`, reasoning effort `medium`) only to extract CRM signals and write a one-line why-now explanation.
- Commit the ranked list as a static JSON artifact. The running app reads that file; it MUST NOT call OpenAI, require `OPENAI_API_KEY`, or recompute ranks in the browser.
- Replace the home-page hero with that ranked provider list (name, organization, tumor focus, incumbent, opportunity patients, why-now line). Keep the three feed cards as secondary “inspect source” links.
- Leave the market-intelligence browse page unordered. Do not add rank columns to the source CSVs or assay markdown. Do not add provider detail routes, objection handling, or meeting scripts in this change.

## Capabilities

### New Capabilities

- `ranked-providers`: Offline hybrid ranking of the committed territory into a static, NPI-keyed worklist. Owns the mix score, GPT-6 Luna extract/explain step, committed artifact schema, and runtime load of that artifact. Does not own source-feed ingest or per-provider briefs.

### Modified Capabilities

- `app-shell`: Home at `/` becomes the ranked call list plus the existing feed overview links. Market intelligence remains an unranked browse page.

## Impact

- **Code**: New `src/lib/ranked-providers/` (schema, mix score, load). New generate script that calls the OpenAI Responses API. New committed JSON under `src/data/ranked-providers/`. Home route loader reads the ranked artifact instead of only rendering static feed cards. `src/lib/browse/server.ts` (or equivalent) exposes the list to `/`.
- **Dependencies**: Official `openai` SDK as a generate-time dependency. Runtime app dependencies stay as they are.
- **Feeds**: No schema changes to market intelligence, product knowledge, or CRM notes. Ranking-layer fields (extracted concern, interest, readiness, why-now copy, score breakdown) live only in the ranked artifact.
- **Out of scope**: Objection handler, meeting script, per-provider detail route, live Salesforce, live Tempus scrape, putting rank on `providers.csv`, ranking only the eight CRM NPIs, calling OpenAI from the site.
- **Assumptions**: Impact is the mix agreed in explore: volume is the backbone; undertest, competitor incumbent, and matched-event recency boost; CRM readiness multiplies; already-Tempus retain accounts drop unless there is an expansion hook. Product-knowledge TAT/gene counts join explanations only, not the numeric score. The committed JSON is regenerated by a documented script, not at `vp dev` / `vp build` time.
