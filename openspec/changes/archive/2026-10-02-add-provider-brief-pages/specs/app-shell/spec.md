# Spec Delta

## MODIFIED Requirements

### Requirement: Home page

The application SHALL render a home page at `/` that shows the committed ranked provider list as the primary content and does not present the previous vanilla Vite starter landing page or its client-only counter. Ranked rows MUST open the per-provider brief route. The home page MUST NOT present Market Intelligence, Product Knowledge, or CRM overview cards.

#### Scenario: Successful home visit

- **WHEN** a user opens `/`
- **THEN** they see a ranked provider list, with no Vite “Get started” copy, no “Count is” counter, and no Market Intelligence, Product Knowledge, or CRM overview cards

#### Scenario: Ranked list is visible

- **WHEN** a user opens `/`
- **THEN** they see providers in rank order with name, organization, tumor focus, incumbent lab, opportunity patient count, and a why-now line

#### Scenario: Home content is in the initial HTML

- **WHEN** a client fetches `/` without executing client JavaScript
- **THEN** the response body includes the home page heading and at least one ranked provider name

#### Scenario: Ranked row opens a brief

- **WHEN** a user activates a ranked provider row on `/`
- **THEN** they navigate to that provider’s brief page

## ADDED Requirements

### Requirement: Provider brief page

The application SHALL render a brief page at a per-provider path keyed by 10-digit NPI. The page SHALL show an overview joined from committed feeds and the ranked artifact, the meeting script from the briefs artifact, and the objection handler when `objection_response` is non-empty. Overview fields MUST NOT be generated by a model at request time. An NPI that is not in the ranked list SHALL use the not-found page.

#### Scenario: Overview is visible

- **WHEN** a user opens the brief page for a ranked provider
- **THEN** they see that provider’s name, organization, tumor focus, incumbent lab, rank, opportunity patient count, why-now line, and any CRM notes for that NPI

#### Scenario: Meeting script is visible

- **WHEN** a user opens the brief page for a ranked provider
- **THEN** they see that provider’s meeting script

#### Scenario: Known objection is visible

- **WHEN** a user opens the brief page for a ranked provider whose `objection_response` is non-empty
- **THEN** they see the drafted objection response

#### Scenario: No concern hides the drafted objection

- **WHEN** a user opens the brief page for a ranked provider whose `objection_response` is empty
- **THEN** they see that no known concern was recorded and they do not see a drafted objection

#### Scenario: Brief content is in the initial HTML

- **WHEN** a client fetches a ranked provider’s brief path without executing client JavaScript
- **THEN** the response body includes that provider’s name and meeting script

#### Scenario: Unknown NPI is not found

- **WHEN** a user opens a provider brief path whose NPI is not in the ranked list
- **THEN** they see the not-found page
