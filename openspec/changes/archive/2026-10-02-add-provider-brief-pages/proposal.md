# Proposal

## Why

The ranked home list tells a rep who to call, but not how to handle that 15-minute CMO or oncologist meeting. The case study’s remaining gap is a per-prospect brief: an overview, a drafted objection response grounded in product metrics, and a 30-second pitch — still without calling a model at request time.

## What Changes

- Remove the Market Intelligence, Product Knowledge, and CRM cards from the home page. Home becomes the ranked call list only. Sidebar browse pages stay so a judge can still inspect the three source feeds.
- Make each ranked row a link to a per-provider brief at `/providers/$npi`. Unknown or unranked NPIs use the existing not-found page.
- Each brief shows an overview joined from committed feeds and the ranked artifact (identity, account, rank, opportunity, why-now, matched events, CRM notes, related assays). Overview copy is not generated by a model.
- Add an offline generate step that writes a committed NPI-keyed briefs JSON using OpenAI GPT-6 Luna (`gpt-6-luna`, reasoning effort `medium`): an objection handler when CRM recorded a known concern, and a 30-second meeting script for every ranked provider. Runtime load MUST NOT call OpenAI or require `OPENAI_API_KEY`.
- Do not invent objections for providers with no CRM concern. Do not write brief copy onto source CSVs, assay markdown, or the ranked-providers artifact.

## Capabilities

### New Capabilities

- `provider-briefs`: Offline, NPI-keyed copilot briefs. Owns the committed briefs artifact, GPT-6 Luna objection and meeting-script generation, grounding against published assay metrics, runtime load, and fail-closed coverage of every ranked provider. Does not own ranking, feed ingest, or browse pages.

### Modified Capabilities

- `app-shell`: Home drops the three feed overview cards and opens a brief route from each ranked row. Adds the per-provider brief page (overview plus generated objection and meeting script).
- `design-system`: Home is no longer required to render the three feed cards. The brief page is composed from shared primitives.

## Impact

- **Code**: New `src/lib/provider-briefs/` (schema, grounding, load). New generate script that calls the OpenAI Responses API and writes `src/data/provider-briefs/briefs.json`. New TanStack route `src/routes/providers.$npi.tsx` (or equivalent). Home table rows become links; feed cards are removed. `src/lib/browse/server.ts` exposes a per-NPI brief loader. Sidebar nav is unchanged.
- **Dependencies**: Reuse the existing `openai` generate-time SDK. No new runtime dependencies.
- **Feeds**: No schema changes to market intelligence, product knowledge, CRM notes, or ranked-providers. Brief copy lives only in the briefs artifact; identity and scores stay joined at read time.
- **Out of scope**: Live Salesforce, live Tempus scrape, calling OpenAI from `vp dev` / `vp build` / route loaders, ranking changes, deleting sidebar browse pages, inventing objections from incumbent when CRM has no concern, putting brief fields on `providers.csv` or `list.json`.
- **Assumptions**: Include the case-study meeting script on the same page as the objection handler (same generate pass). Every ranked provider gets a page and a meeting script; the objection block is empty unless CRM extracted a non-empty concern. Model and effort match ranking (`gpt-6-luna`, `medium`). The eight CRM NPIs are the objection showcase (Quinn Chen TAT vs Guardant is the canonical example).
